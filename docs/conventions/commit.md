# 커밋 컨벤션

## 구조

제목, 본문, 꼬리말을 빈 줄로 구분한다.

```
<Type>: <Subject>

<Body>

<Footer>
```

- 콜론(`:`) 앞에는 공백을 두지 않고, 뒤에만 공백 한 칸을 둔다.

## Type

영어로 쓰고 첫 글자만 대문자로 쓴다.

| Type | 용도 |
| --- | --- |
| `Feat` | 새로운 기능 추가 |
| `Fix` | 버그 수정 |
| `Docs` | 문서 수정 |
| `Style` | 코드 포맷팅, 세미콜론 누락 등 동작 변경이 없는 수정 |
| `Refactor` | 코드 리팩토링 |
| `Test` | 테스트 코드 추가·수정 |
| `Chore` | 빌드 작업, 패키지 매니저 수정 |
| `Config` | 설정 수정 |

## Subject

- 50자를 넘기지 않는다.
- 마침표와 특수기호를 쓰지 않는다. 따옴표로 감싸지 않는다.
- 문장이 아니라 개조식으로 간결하게 쓴다. 예: `회원 가입 기능 구현`
- 영문으로 쓸 때는 동사 원형을 맨 앞에 두고 첫 글자를 대문자로 쓴다. 과거형을 쓰지 않는다.
  - `Fixed` → `Fix`, `Added` → `Add`, `Modified` → `Modify`

## Body

- 길이 제한 없이 최대한 자세히 쓴다.
- 어떻게 바꿨는지보다 **무엇을, 왜** 바꿨는지 설명한다.

## Footer (선택)

관련 Jira 이슈를 `<유형>: <이슈 키>` 형식으로 쓴다. 이슈가 여러 개면 쉼표로 구분한다.

| 유형 | 용도 |
| --- | --- |
| `Fixes` | 이슈를 수정 중 (아직 해결 전) |
| `Resolves` | 이슈를 해결함 |
| `Ref` | 참고할 이슈 |
| `Related to` | 관련 이슈 (아직 해결 전) |

## 예시

```
Feat: 회원 가입 기능 구현

SMS, 이메일 중복확인 API 개발

Resolves: S15P31A109-123
Ref: S15P31A109-456
Related to: S15P31A109-48, S15P31A109-45
```
