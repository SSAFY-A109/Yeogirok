# API 통신 및 TanStack Query

이 규칙은 서버 통신 계층을 도입한 이후의 코드에 적용한다. 계층을 처음 도입하는 일(axios, TanStack Query 설치와 `api/client.ts` 생성)은 승인 후 진행한다. 절차와 예시는 `docs/api-guide.md`에 있다.

## 호출 계층

- API 호출은 `화면/컴포넌트 → Query/Mutation Hook → Options 팩토리 → 도메인 API 함수 → api/client.ts` 순서를 따른다.
- `api/client.ts`의 공용 `api` 인스턴스는 도메인 API 함수만 호출할 수 있다.
- 컴포넌트와 화면에서는 `fetch`, `axios`, `api.get`, `api.post`나 도메인 API 함수를 직접 호출하지 않는다.
- 도메인 API 함수에 목 분기(`if (mocked) return …`)를 두지 않는다. 목은 네트워크 계층의 MSW가 담당한다(규칙 90 목 서버).

## Query

- 서버 데이터는 TanStack Query로만 다룬다.
- `useEffect`와 `useState`를 조합해 서버 요청 결과를 보관하지 않는다.
- 조회 요청은 도메인별 `xxxKeys` 팩토리와 `queryOptions` 팩토리로 정의한다.
- Query Key에는 그 요청에 영향을 주는 모든 입력값을 넣는다.
- Query Key에는 직렬화할 수 있는 값만 쓴다.
- Query 함수가 받은 `AbortSignal`을 API 클라이언트까지 전달해, 필요 없어진 요청을 취소할 수 있게 한다.
- 같은 요청의 `staleTime`, `gcTime`, `retry`, `refetchInterval` 정책은 Options 팩토리에 정의한다. 컴포넌트마다 다르게 지정하지 않는다.

## 화면 영역(지도) 조회

방문 분포도(API-046), 코스·장소 지도 표시처럼 화면에 보이는 영역으로 조회하는 요청에 적용한다.

- Query Key에는 영역(남서·북동 좌표), 줌, 카테고리 같은 필터를 모두 넣는다. 좌표는 캐시가 맞도록 정해진 자릿수로 반올림한 값을 쓰고, 자릿수는 해당 도메인 `queries.ts`의 상수로 둔다.
- 지도를 움직이는 동안에는 요청하지 않는다. 이동이 멈춘 뒤 디바운스해서 조회하고, 새 영역을 받는 동안 이전 결과는 `placeholderData: keepPreviousData`로 유지한다.
- 영역 형식·범위는 요청 전에 검증한다. 서버의 C017(지도 조회 영역 오류)이 오면 재시도하지 않고 보고한다.

## 비동기 작업 (Job)

AI 일정 초안(API-037), AI 기록 초안(API-064), AR 팁 등록(API-049)처럼 서버가 작업을 만들고 나중에 결과를 주는 요청에 적용한다.

- 처리 순서
  1. 작업 생성은 `useMutation`으로 한다.
  2. 진행 상태는 작업 id를 키로 한 `useQuery`로 조회한다(API-011 작업 상태 또는 도메인 조회 API). 폴링은 `refetchInterval`로 하고, 완료·실패 상태가 되면 멈춘다.
  3. 완료되면 결과 쿼리를 무효화한다.
- 폴링 간격과 최대 대기 시간은 Options 팩토리의 상수로 둔다. 최대 대기를 넘기면 "아직 처리 중"을 안내하고 다시 확인할 수단을 준다. 폴링 요청이 실패한 것을 작업 실패로 표시하지 않는다.
- 사용자가 화면을 벗어나도 작업은 서버에서 계속된다. 다시 들어오면 서버 상태(작업 목록·도메인 조회)로 진행 상태를 복원한다. 작업 id를 기기 저장소에만 의존해 보관하지 않는다.
- 작업 생성 요청은 멱등성 키로 중복 생성을 막는다(규칙 90).

## 파일 업로드

- 사진·영수증은 업로드(API-012)와 연결(예: API-062 자료 연결, API-068 사진 연결)을 별개의 mutation으로 나눈다. 연결 요청에는 업로드가 끝난 `mediaId`만 보낸다.
- 여러 파일을 올릴 때는 파일별로 진행률·실패·재시도를 관리한다. 실패한 파일만 다시 올리고, 성공한 파일을 다시 보내지 않는다.
- 업로드는 조회용이 아니라 업로드용 타임아웃 상수를 쓴다(규칙 90).

## Mutation

- 변경 요청은 도메인별 Mutation 함수와 `mutationOptions` 팩토리로 정의한다.
- Mutation이 성공한 뒤 서버 응답으로 캐시를 직접 갱신할지, 관련 쿼리를 무효화할지 명확히 정한다. 정한 내용은 `docs/api-guide.md` §5 무효화 지도에 적는다.
- 낙관적 업데이트를 적용했다면 오류가 났을 때 이전 캐시 상태로 롤백한다. 낙관적 업데이트는 실패해도 되돌릴 수 있는 토글(팁 반응, 즐겨찾기)에만 쓴다. 발자취 저장, 코스 공개, AI 결과 적용에는 쓰지 않는다.
- 인증·권한·검증 오류처럼 재시도로 해결되지 않는 오류는 재시도하지 않는다. 위치 증거 오류(C012~C014)는 자동 재시도하지 않고, 사용자가 다시 측정하게 안내한다.
- 요청 중에는 같은 작업이 중복 실행되지 않도록 제출 상태와 상호작용을 막는다.

## 여러 명이 고치는 자원

- 여행방 일정(API-040), 여행 기록(API-066·067)처럼 일행이 함께 고치는 자원은 계약이 정한 버전 값을 함께 보낸다.
- 409 C008(버전 불일치)이 오면 조용히 덮어쓰지 않는다. 최신 상태를 다시 불러오고, 사용자의 변경이 반영되지 않았다는 사실과 다시 적용할 수단을 보여준다. 충돌 해결 방식은 DEC-12 결정 전까지 이 기본값을 쓴다.
