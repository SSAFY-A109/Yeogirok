# yeogirok-ui-patterns

여기록 화면은 "다른 사람의 경험을 내 여행으로 가져오고, 내 경험을 다시 공유하는" 흐름이 끊기지 않는 것이 먼저다.

이 스킬은 자주 나오는 화면 단위의 요구사항과 구현 기준을 모아 둔다.
- 값: `design/tokens.json`
- 의도: `design/DESIGN.md`
- 위치·사진·공개 범위: `.agents/rules/80-location-media-ugc.md`
- 네이티브 모듈: `.agents/rules/85-native-modules.md`
- 기능 ID와 우선순위: `docs/frontend-spec.md`

## 공통 원칙

- **상태 5종을 빠짐없이 둔다.** 아래 다섯 상태가 없는 화면은 완성이 아니다.
  - 로딩: `Skeleton`
  - 빈 상태: `EmptyState`. 화면별 문구는 frontend-spec §4를 따른다.
  - 오류: 발생한 범위 안에서 안내 + 재시도
  - 권한 필요: `PermissionGate`
  - 처리 중: 작업 진행 단계 표시
  - 처리 상태와 재시도는 명세 COM-05에 해당한다.
- **확인되지 않은 값을 확정값처럼 보여주지 않는다.** 이동 시간·주차 정보가 없으면 "정보 없음"으로 표시하고 0분이나 "주차 가능"으로 채우지 않는다. AI가 추측한 방문은 "확인 필요"로 표시한다(명세 §7).
- **AI 결과는 초안이다.** 생성 중 → 초안(사용자가 고칠 수 있음) → 적용·완성의 세 단계를 화면에서 구분한다. 적용하기 전에는 기존 일정·기록을 바꾸지 않는다.
- **권한은 기능 진입 시점에 요청한다.** 사전 안내 → OS 대화상자 → 거부 시 이유와 "설정 열기"를 보여준다. 위치·카메라가 없어도 쓸 수 있는 기능(계획·기록)은 막지 않는다.
- **공개 범위를 화면에서 넘지 않는다.** 방명록은 본인만 볼 수 있다. 지도에는 집계 분포만 그리고, 개인 방문자나 동선은 그리지 않는다.
- 모든 터치 요소는 다음을 지킨다.
  - 크기 44pt 이상, 간격 8 이상
  - `accessibilityRole`과 `accessibilityLabel`
  - 시연 흐름에 쓰이는 요소에는 `testID`(`<화면>.<요소>`, 규칙 60)
- 색은 `DESIGN.md` §2의 토큰만 쓴다. 지도 색은 `lib/theme.ts`의 `map-*`로 넘긴다. 코랄(`highlight`)은 발자취에만 제한적으로 쓴다.

`references/patterns.md`에 패턴별 체크리스트가 있다. 작업 전에 해당 항목을 읽는다.

| PermissionGate | COM-03·04 | 위치·카메라·사진 사전 안내, 거부·영구 거부·미지원 상태 |
| JobProgress | COM-05 | 비동기 작업(AI 초안·팁 게시) 진행 단계, 실패·재시도, 화면 이탈 후 복원 |
| CourseCard · CourseDetail | EXP-03~05 | 대표 사진·지역·일수·장소 수. 상세는 날짜별 장소 목록 + 지도 |
| PlacePicker | EXP-07·08 | 코스에서 장소 다중 선택 → 가져올 여행방 선택 시트(새 여행방 만들기 포함) |
| RoomPlaces | TRP-04·05·07 | 담은 장소 목록, 출처 표시(코스·검색·AI 추천), 빼기 |
| RecommendFlow | PLN-01~03 | 추천 조건 입력 → 결과 → 담기·싫어요 |
| ScheduleTimeline | TRP-08~10 | 이동 수단, 날짜 탭, 방문 순서·시각·체류, 이동 시간·주차, AI 초안 비교·적용, 직접 조정 |
| MapExplore | EXP-01·02, FPT-07 | 방문 분포도(집계), 카테고리 칩, 영역 이동 재조회 |

| RecordDraft | REC-05·06 | 영수증·사진 → AI 초안, 확정·추정·보류 구분, 확인 후 반영 |
| RecordTimeline | REC-02·07·08·09 | 일정별 사진·이야기, 작성자 표시, 완성 처리 |

## 구현 순서 (화면 하나 기준)

1. `docs/frontend-spec.md`에서 기능 ID·우선순위·연결 API를 확인한다. P1·P2는 요청이 있을 때만 만든다.
2. `design/design-map.json`에서 Pencil 노드를 확인한다.
   - 노드가 있으면 `pencil-design` 절차 B로 대조한다.
   - `없음`이면 Figma 와이어프레임(Wxx)을 참고로 `DESIGN.md` 기준으로 구현하고, "Pencil 미대조"로 표시한다.
3. `references/patterns.md`에서 해당 패턴의 체크리스트를 읽는다.
4. 화면 모델(`features/<domain>/model.ts`)과 Query/Mutation 훅을 먼저 정의한다(규칙 20·90). 백엔드가 없으면 MSW 핸들러로 화면을 만든다.
5. 공용 컴포넌트가 없으면 `components/ui/`에 인벤토리 이름으로 만든다(`DESIGN.md` 5장).
6. 상태 5종과 접근성·`testID`를 함께 구현한다.
7. `pnpm tokens:check`, `pnpm typecheck`를 실행해 통과를 확인한다. 네이티브 모듈이 걸리면 실기기 확인 여부를 보고한다(규칙 85).
8. P0 시연 흐름이 완성되면 Maestro flow를 추가한다(규칙 60).

## 금지

- 다른 사용자의 방명록 본문, 방문자 명단, 개인 동선을 화면에 만들지 않는다.
- 방명록 작성과 AR 팁 등록을 한 동작으로 묶지 않는다(DEC-06 전 기본값).
- AI 초안이나 추정 방문을 사용자 확인 없이 확정 저장하지 않는다.
- 없는 이동·주차 정보를 기본값으로 채우지 않는다.
- 앱 시작 시 권한을 한꺼번에 요청하지 않는다.
