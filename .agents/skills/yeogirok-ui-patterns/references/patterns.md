# 여기록 화면 패턴 체크리스트

각 항목의 기능 ID는 `docs/frontend-spec.md` §1, API 번호는 `docs/api-contract.md` §2와 같다. "결정 필요(DEC-xx)"는 결정 전까지 기본값으로 만들고, 보고서에 `TBD`로 남긴다.

## TabBar (COM-02)

- [ ] 탭은 5개다: 메인 페이지 · 여행방 관리 · AR 팁 · 기록 · 지도. 중앙 + 버튼은 없다(명세 v0.2).
- [ ] My는 탭이 아니다. 메인 페이지 상단에서 진입한다(하위 화면 범위는 DEC-21).
- [ ] 활성 탭은 `text-icon-active` + `text-label`로, 비활성 탭은 `text-icon`으로 표시한다. 탭 자체가 위치를 알려 주므로 탭 화면에 제목 헤더를 두지 않는다(규칙 40).
- [ ] AR 팁 탭으로 갈 때 카메라 권한이 없으면 탭 화면 안에서 `PermissionGate`를 보여준다. 탭 이동 자체를 막지 않는다.
- [ ] 탭을 바꾸면 카메라·AR·위치 구독을 해제한다(규칙 85).

## PermissionGate (COM-03 위치, COM-04 카메라·사진)

- [ ] 상태 4개: 안내 전(사전 안내 화면) / 허용 / 거부(다시 요청 가능) / 영구 거부(설정 열기만 가능). AR은 "기기 미지원" 상태가 하나 더 있다.
- [ ] 사전 안내에는 무엇에 쓰는지 한 문장으로 쓴다. 예: "지금 있는 곳에 발자취를 남기려면 위치가 필요해요".
- [ ] 거부해도 할 수 있는 다음 행동을 준다. 예: AR 대신 지도에서 보기, 위치 없이 계획 계속하기.
- [ ] 입력 중이던 내용(방명록 본문 등)은 권한 흐름을 거친 뒤에도 유지한다.

## JobProgress (COM-05)

- [ ] 작업 생성 직후 화면이 바로 진행 상태로 바뀐다. 버튼은 비활성이고, 멱등성 키를 붙인다.
- [ ] 단계가 있으면 단계를 보여준다. 예: 사진 읽음 → 영수증 읽음 → 둘 맞추기(Figma W21). 단계가 없으면 "만들고 있어요"와 경과를 표시한다.
- [ ] 실패하면 이유(작업 결과의 code)와 재시도를 보여준다. 폴링 요청 자체의 실패는 작업 실패로 표시하지 않는다.
- [ ] 화면을 벗어났다가 돌아오면 서버 상태로 진행 상태를 복원한다.

## CourseCard · CourseDetail (EXP-03·04·05)

- [ ] 검색(API-014)은 필터 칩(`FilterChip`, 지역·카테고리)과 검색 필드(`SearchField`)로 한다. 필터 값은 라우트 파라미터에 둔다(규칙 10).
- [ ] 카드에는 대표 사진, 제목, 지역, 일수, 장소 수를 둔다. 사진이 없으면 `muted` 배경과 아이콘을 쓴다.
- [ ] 상세(API-016)에는 날짜 탭 + 장소 목록 + 지도(`map-route`, `map-pin`)를 둔다. 코스에 담긴 발자취·팁이 있으면 하이라이트로 보여준다(코랄 배지 `bg-highlight-muted text-highlight`).
- [ ] 원본 코스가 삭제되었거나 비공개로 바뀌면 "이용할 수 없는 코스"로 안내한다(가져간 일정의 유지 정책은 DEC-18).

## PlacePicker (EXP-07·08)

- [ ] 코스 상세에서 장소를 여러 개 선택한다. 선택 수를 하단 고정 CTA에 표시한다. 예: "3곳 여행방에 담기".
- [ ] CTA를 누르면 여행방 선택 바텀시트(API-020)를 연다. 맨 위에 "새 여행방 만들기"(API-021)를 둔다.
- [ ] 가져오기(API-030)가 성공하면 해당 여행방으로 이동하거나 토스트로 바로가기를 준다. 이미 담긴 장소는 서버 응답대로 표시한다.

## RoomPlaces (TRP-04·05·07)

- [ ] 담은 장소마다 출처(코스에서 / 검색 / AI 추천)와 담은 사람을 표시한다.
- [ ] 장소 검색(API-026) → 상세(API-027, 주차 정보) → 담기(API-029). 빼기(API-032)는 확인 없이 하되 되돌리기 토스트를 둔다 `[확인]`.
- [ ] 여행지 모아 보기(TRP-07, 지도 핀)는 P1이다. 요청이 있을 때만 만든다.

## RecommendFlow (PLN-01·02·03)

- [ ] 추천 조건 입력(API-033): 지역·컨셉 칩을 쓴다. 선택지는 서버 기준 데이터(API-078·079·010)로 받고 하드코딩하지 않는다.
- [ ] 결과(API-034): 장소 카드에 "담기"와 "싫어요"(API-035)를 둔다. 싫어요는 되돌릴 수 있게 한다.
- [ ] API-033·080 중복이 정리되기 전에는 API-033을 쓰고 보고서에 `TBD`로 남긴다.

## ScheduleTimeline (TRP-08·09·10)

- [ ] 이동 수단(API-023, 자차·대중교통)을 바꾸면 기존 초안은 낡은 것으로 표시하고 다시 만들기를 안내한다.
- [ ] AI 초안 생성(API-037, 작업) → 초안 조회(API-038) → 적용(API-039).
  - 초안에서는 현재 일정과 달라지는 점(순서, 빠진 장소)을 보여준다.
  - 시간 안에 다 방문할 수 없으면 그 사실을 안내한다(명세 §7).
- [ ] 일정 항목에는 시각, 장소, 체류 시간, 다음 장소까지 이동 시간을 둔다. 자차라면 주차 정보도 둔다. 정보가 없으면 "정보 없음"으로 표시한다.
- [ ] 직접 조정(API-040): 순서 이동, 시각·체류 수정, 순서 고정. 409 C008이면 최신 일정을 다시 불러와 반영되지 않았음을 알린다.
- [ ] "기록 만들기"(TRP-12, API-057)는 여행이 끝난 뒤 보이는 주요 CTA다.

## MapExplore (EXP-01·02, FPT-07)

- [ ] 방문 분포도(API-046)는 서버 집계값만 그린다(히트·원·숫자 마커). 개인 단위 점은 그리지 않는다.
- [ ] 카테고리 칩으로 필터한다. 영역을 옮긴 뒤 디바운스해서 재조회하고, 이전 결과는 유지한다(규칙 20).
- [ ] 발자취 핀(`map-footprint`)에는 흰 테두리를 준다. 현재 위치 마커와 구분한다.
- [ ] "발자취 남기기" 버튼은 지도 탭에서 바로 진입한다(FPT-01). 위치 권한이 없으면 `PermissionGate`로 보낸다.

## FootprintComposer (FPT-01·02·03·08)

- [ ] 현재 위치 확인(FPT-02): 지도에 내 위치와 정확도 반경을 보여준다. 정확도가 낮으면 다시 측정하도록 안내한다(기준은 서버, DEC-01).
- [ ] 방명록 입력. 최소 입력(DEC-04)이 정해지기 전에는 본문을 선택 입력으로 둔다. "나만 볼 수 있어요"를 입력창 근처에 항상 표시한다.
- [ ] 저장(API-041)할 때 위치 증거와 멱등성 키를 함께 보낸다. C012~C014 오류에는 "위치 다시 확인" 버튼을 보여주고, 입력한 본문은 유지한다.
- [ ] 저장에 성공하면 방문 분포도 쿼리를 무효화한다. 팁을 자동으로 만들지 않는다(DEC-06).

## ArTip (TIP-01~10)

- [ ] 진입(TIP-01): 기기 지원과 카메라 권한을 확인한다. 화면 구성은 카메라가 화면을 채우고, 우측 상단에 지도 오버레이를 둔다(영역 범위는 DEC-22).
- [ ] 추적 상태(초기화 중·불안정·조명 부족)를 상단에 표시한다.
- [ ] 탐색(TIP-02, API-047): 위치 증거와 함께 요청한다. 주변 팁이 없으면 빈 상태로 보여주고 "나도 올리기"를 둔다. 오류로 표시하지 않는다.
- [ ] 상세(TIP-03, API-048): 본문, 사진, 반응(TIP-04, API-052 낙관적 반영)을 보여준다. 공간 복원 실패(TIP-10)는 "팁 없음"과 구분한다.
- [ ] 등록 흐름: 작성 시작(TIP-05) → 위치 배치(TIP-06) → 본문(TIP-07) → 사진(TIP-08, 업로드 → EXIF 위치 제거) → 공개 등록(TIP-09, API-049 작업). 게시가 끝날 때까지 "게시 중" 상태를 보여주고 중복 등록을 막는다.
- [ ] 화면을 벗어나거나 앱이 백그라운드로 가면 AR 세션과 카메라를 즉시 멈춘다.

## UploadQueue (REC-04·07, TIP-08)

- [ ] 파일 선택은 시스템 사진 선택기로 한다. 여러 장을 고를 수 있다.
- [ ] 파일별로 썸네일, 진행률, 실패 아이콘, 재시도를 둔다. 전체 진행은 "8/14장"처럼 표시한다.
- [ ] 업로드(API-012)가 끝난 `mediaId`만 연결 요청(API-062·068)에 쓴다. 실패한 파일만 다시 올린다.
- [ ] 기록 공간에서는 누가 몇 장 올렸는지 표시한다(Figma W21).
- [ ] 화면을 벗어나면 대기열이 어떻게 되는지 안내한다(계속 / 취소).

## RecordDraft (REC-05·06)

- [ ] 초안 생성(API-064, 작업) → 조회(API-065). 진행 단계는 JobProgress를 따른다.
- [ ] 초안 항목은 상태 3가지로 구분한다(Figma W22).
  - 확정: 영수증과 사진이 맞음
  - 추정: 위치가 애매함 → "확인 필요" 배지
  - 보류: 위치 없는 사진 → 넣을 일정을 사용자가 고른다
- [ ] 인식에 실패한 영수증이나 장소가 불분명한 항목은 사용자가 직접 추가·수정한다. 추정 항목을 확정 방문으로 저장하지 않는다.
- [ ] 금액은 `lib/money.ts` 포맷 + `tabular-nums`로 표시하고, 합계는 서버 값을 쓴다. 카드번호는 마스킹한다(규칙 80).
- [ ] 확인을 반영(API-066)한 뒤 실제 일정 편집(API-067)으로 넘어간다.

## RecordTimeline (REC-01·02·07·08·09)

- [ ] 목록(REC-01): 기록 카드에 상태 배지를 단다(작성 중 / 완성 / 코스 공개 중 — `Badge` Tone Neutral·Success·Brand).
- [ ] 상세(REC-02)는 읽기 전용이다. 표지, 요약 숫자(다녀간 곳·사진·이야기), 실제 동선 지도, 타임라인을 둔다. 결제 금액의 공개 범위는 DEC-16을 따른다.
- [ ] 편집: 일정별 사진(API-068), 이야기(API-069·070, 작성자 아바타)를 다룬다. 이야기가 없는 일정에는 빈 상태 문구를 보여준다.
- [ ] 완성(REC-09, API-071) 뒤에도 다시 편집할 수 있는지는 명세를 따른다.

## PublishPreview (REC-10·12)

- [ ] 미리보기(API-072)에는 다른 사람에게 보일 장소, 순서, 사진, 설명을 그대로 보여준다. 공개에서 빠지는 정보(방명록, 결제 자료)는 "공개되지 않아요"로 명시한다.
- [ ] 일행이 올린 사진의 공개 동의 처리는 계약이 정해질 때까지 `TBD`로 둔다. 임의로 공개하지 않는다.
- [ ] 게시(API-073)에는 멱등성 키를 붙이고 자동 재시도하지 않는다. 성공하면 상세가 "공개 중" 상태로 바뀐다.
- [ ] 공유 코스 관리(REC-12, API-074·075): 수정과 공개 해제를 한다. 해제는 확인 대화상자를 거친다. 이미 가져간 다른 사람의 일정이 어떻게 되는지는 DEC-18을 따른다.
