# 계획 일정 결정 사항

> 계획 일정(API-036~040·084)을 만들면서 정한 규칙이다. 원천은 팀 Notion "API 명세"이고, 명세에 없는 값은 여기 적는다.
> 명세와 이 문서가 다르면 명세를 먼저 고치고 이 문서를 맞춘다.

## 1. 흐름

| 단계 | API | 비고 |
| --- | --- | --- |
| 조건 입력 → 초안 생성 | 037 | 비동기(202). 날짜가 정해지고 후보가 3곳 이상일 때 |
| 초안 조회 | 038 | |
| 서버 재계산 미리보기 | 084 | 선택. 사용자가 "다시 계산"을 누를 때만 |
| 편집한 초안 저장 | 039 | 전체 편집 상태를 한 번에 보낸다 |
| 확정 일정 조회 | 036 | 022 의 `schedule` 도 같은 구조 |
| 확정 일정 직접 편집 | 040 | 화면의 "일정 조정하기"는 040 이 아니라 037(`fixedItems`) → 084 → 039 를 쓴다 |

## 2. 결정 사항

### 조건 (11/6)

- **하루 일정 밀도(pace)는 없앤다.** 여유롭게·보통·빼곡하게 선택을 받지 않는다.
- **출발·도착 지점**은 첫날 출발지(`startPoint`)와 마지막 날 도착지(`endPoint`) 둘만 받는다. 둘 다 선택이다.
  - 역·터미널을 받을 것으로 보지만 종류 제약은 두지 않는다(혼자 여행이면 집일 수도 있다).
  - 숙소는 따로 받지 않는다. 그 밖의 날(중간 날, 첫날 도착, 마지막 날 출발)은 지점이 없다.
  - 당일치기는 같은 날에 출발지와 도착지를 모두 적용한다.
  - 지점이 없는 날은 첫 장소에 그날 시작 시각으로 도착하고, 마지막 장소 뒤에는 이동 구간이 없다. 임의 지점을 만들지 않는다.
- **체류 시간**은 새로 배치할 때 60분이고, 사용자가 **1분 단위로 1~720분**(최대 12시간) 사이에서 고칠 수 있다.
  0분·720분 초과는 C003, 음수는 SC006. DB 에도 `CHECK (stay_minutes BETWEEN 1 AND 720)` 이 있다(ERD).

### 식사 배치 (11/6, 초안 생성·재계산에 적용)

- 맛집은 후보의 카테고리가 `FOOD` 인 장소다. 카테고리가 없는 후보(지도 핀 직접 추가)는 맛집으로 보지 않는다.
- 점심은 **도착 시각이 11:00~14:00** 사이가 되도록 넣는다.
- 저녁은 **도착 시각이 17:00~20:00** 사이이면서 **그날 점심 도착 시각 + 5시간 이후**가 되도록 넣는다. 그날 점심이 없으면 시간대 조건만 본다.
  - 5시간은 "밥이 들어갈 만큼 띄운다"는 뜻의 대략값이다. 기준은 도착 시각으로 정했다.
- 맛집이 모자라면 **모든 날의 점심을 먼저** 채우고, 남는 맛집으로 저녁을 채운다.
- 그날 시작~종료 시각 안에 식사 시간대가 들어가지 않으면 그 끼니는 넣지 않는다.
- 식사 여부는 응답에 따로 표시하지 않는다(점심 태그 없음). 항목은 다른 장소와 같은 모양이다.

### 응답 모양 (Notion 11/6 수정 반영)

- `Schedule` 에는 별도 `id` 가 없다. 방마다 일정은 하나이고 경로의 `roomId` 로 식별한다.
- 확정 `schedule_items` 가 한 개도 없으면 `schedule` 은 `null` 이다.
- `startPoint`·`endPoint` 는 `Schedule` 에 하나씩 있다(일차마다 두지 않는다). 지점은 `{name: string|null, latitude, longitude}`.
- `unassignedPlaces` 는 `roomPlaceId` 만 준다(초안은 `itemId` 도). 못 넣은 이유·추천 날짜는 주지 않는다.
- `warnings` 는 `ScheduleWarning` 코드 배열이다(API-036 "일정 응답 공통 규칙"). 같은 범위에서 같은 코드를 중복하지 않는다.

| 값 | 뜻 |
| --- | --- |
| `TRAVEL_TIME_UNAVAILABLE` | 그날 구간 중 이동 시간을 모르는 것이 있다 |
| `ARRIVAL_TIME_UNKNOWN` | 도착 시각을 모르는 항목이 있다 |
| `END_TIME_EXCEEDED` | 마지막 일정(도착지가 있으면 도착지 도착)이 그날 종료 시각을 넘는다 |

### 여행방 수정(API-023)과 일정

- 날짜를 줄이면 새 날짜 밖 항목을 확정 일정에서 지운다. 후보 장소는 그대로다.
- 저장할 때 **날짜나 이동 수단이 바뀌면** 남은 항목의 이동 시간·시각을 다시 계산한다. 날짜가 바뀌면 첫날 출발지·마지막 날
  도착지가 붙는 날도 바뀌기 때문이다.
- 일정이 있는 방의 날짜를 지우면(null) C003.

### 이동 시간

- 카카오 REST API 키 하나로 부른다(`KAKAO_REST_API_KEY`).
  - `CAR`: 카카오모빌리티 자동차 길찾기(추천 경로 요약)
  - `TRANSIT`: 카카오맵 대중교통 경로 조회 중 가장 빠른 경로. 경로가 없고 직선 2km 안이면 도보 경로로 대신한다
- 초는 분으로 올림한다. 출발 시각을 넣을 수 없어 시간대별 교통 상황·배차는 반영하지 않는다.
- 키가 없거나 호출이 실패하면 이동 시간을 `null` 로 두고 경고를 붙인다. 근거 없는 이동 시간·시각을 만들지 않는다(명세 정책).
- 2026-11-06 실제 키로 세 API 응답 모양을 확인했다.
