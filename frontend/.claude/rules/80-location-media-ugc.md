# 위치·사진·사용자 콘텐츠의 보안과 공개 범위

이 규칙은 `50-error-security.md`에 더해 여기록(발자취·AR 팁·여행 기록)의 특성에 따라 적용하며, 충돌하면 이 규칙이 우선한다. 근거 문서는 기능 명세서 v2(§2 용어와 공개 범위, §7 권한과 예외 처리)와 API 명세의 공통 실패 코드(C012~C017)다. 명세가 "결정 필요(DEC-xx)"로 둔 값은 임의로 정하지 않고 `TBD`로 보고한다.

## 위치

- 위치 권한은 **앱 사용 중(foreground)**만 요청한다. 백그라운드 위치 권한과 상시 추적은 요구사항에 없으므로 요청하지 않는다. 필요해지면 명세를 바꾼 뒤 승인을 받는다.
- 권한은 기능에 진입할 때 요청한다. 발자취 남기기(FPT-01)와 AR 팁(TIP-01) 진입 시 사전 안내 화면(COM-03)을 먼저 보여주고, 그다음 OS 대화상자를 띄운다. 앱을 시작할 때 권한을 한꺼번에 요청하지 않는다.
- 권한 거부나 위치 확인 실패 시에는 다음을 지킨다(명세 §7).
  - 이유와 재시도 수단을 보여준다.
  - 발자취를 저장하거나 방문 통계를 늘리지 않는다.
  - 사용자가 입력한 방명록 본문은 유지한다.
- 현재 위치가 필요한 요청(발자취 저장 API-041, 팁 탐색·등록 API-047·049)에는 좌표와 함께 정확도(m)와 측정 시각을 **위치 증거**로 보낸다. 필드 형식은 계약 사본(`docs/api-contract.md` §1)을 따른다.
- 정확도와 유효 시각의 기준(DEC-01)은 서버가 판정한다(C012 누락·C013 만료·C014 정확도 미달). 클라이언트는 기준 값을 하드코딩해 막거나 통과시키지 않는다. 오류 code별로 다시 측정하도록 안내한다.
- 클라이언트 좌표는 모의 위치 앱으로 위조할 수 있다. 현장 방문 인정은 서버 판정만 신뢰하고, 클라이언트 검사는 UX 보조로만 쓴다.
- 위경도 범위(C015)와 지도 조회 영역 형식(C017)은 요청 전에 `model.ts`·쿼리 옵션에서 검증한다.
- 좌표를 로그, 분석 이벤트, 오류 리포트에 넣지 않는다. 필요한 문맥은 요청 id와 오류 code로 한정한다.

## 공개 범위

콘텐츠마다 공개 범위가 정해져 있다(명세 §2). 화면은 이 범위를 넘는 정보를 만들거나 보여주지 않는다.

| 콘텐츠 | 볼 수 있는 사람 | 화면에서 지킬 것 |
| --- | --- | --- |
| 발자취 방명록 | 작성자 본인 | 다른 사용자에게는 서버 집계 통계(방문 분포도)만 보여준다. 방문자 명단, 개인별 방문 동선, 다른 사람의 방명록 본문을 만들지 않는다 |
| AR 팁 | 현장 조건을 충족한 이용자(공개) | 팁 본문은 현장 AR에서 연다. 현장 밖 노출 범위는 DEC-22 결정 전까지 명세 그대로 |
| 여행방 계획·채팅 | 여행방 참여자 | 초대 링크로 들어온 사용자는 참여 확인 후에만 내용을 본다 |
| 공개 전 여행 기록·추출 자료 | 기록 참여자 | 영수증·결제 자료는 참여자 범위를 벗어나지 않는다 |
| 공유 코스 | 서비스 이용자 | 공개 대상으로 고른 장소·순서·사진·설명만 나간다 |

- 방문 분포도는 서버가 집계한 값만 그린다. 클라이언트에서 개별 좌표를 모아 분포를 다시 만들지 않는다. 표시 정밀도(DEC-07)는 서버 값을 따른다.
- 방명록과 AR 팁은 별개 콘텐츠다. 방명록을 쓰면서 팁을 자동으로 만들지 않는다. 팁을 등록하면서 발자취를 자동으로 남기지 않는다. DEC-06 결정 전 기본값은 "사용자가 따로 선택할 때만"이다.
- 코스를 공개하기 전(REC-10)에는 공개될 장소·사진·설명을 사용자가 확인하는 단계를 둔다(API-072 미리보기). 일행이 올린 사진의 공개 동의 처리는 계약에 정해질 때까지 `TBD`로 두고, 임의로 처리하지 않는다.

## 카메라·사진

- 카메라·사진 권한도 기능 진입 시점에 사전 안내(COM-04)를 거친 뒤 요청한다. 사진은 가능하면 시스템 사진 선택기로 받아, 보관함 전체 접근 권한을 요구하지 않는다.
- 파일 업로드는 API-012(`POST /media`)로 먼저 올리고, 받은 `mediaId`로 연결 요청을 보낸다(규칙 20 업로드). 진행률·실패·재시도를 파일별로 보여주고, 실패한 파일만 다시 보낸다.
- 공개 범위로 바로 나가는 사진(AR 팁 첨부 TIP-08)은 업로드 전에 EXIF 위치 정보를 제거한다.
- 기록 사진은 AI 기록 초안(REC-05)의 일정 매칭에 촬영 시각·위치가 필요하므로 원본 메타데이터를 보낸다. 이 사진이 공유 코스로 나갈 때 위치 메타데이터를 누가 제거하는지는 계약에서 확인한다(`TBD`).
- 사진은 API-013 접근 URL로 표시한다. 접근 URL은 만료될 수 있으므로 영구 저장소·로그에 남기지 않고, 만료되면 다시 조회한다.

## 영수증·결제 자료

- 영수증·결제 자료는 기록 참여자 범위의 데이터다. 카드번호·승인번호는 `lib/mask.ts`로 마스킹해서만 표시한다. OCR 원문과 이미지 URL은 로그·분석 이벤트에 넣지 않는다. 입력·보관 범위는 DEC-16을 따른다.
- 금액은 경비 표시용이다. 표시는 `lib/money.ts`의 포맷터만 쓰고 `tabular-nums`를 함께 쓴다. 합계 등 서버가 계산해 내려주는 값은 클라이언트에서 다시 계산하지 않는다.
- AI가 추출한 항목(영수증 인식, 사진 위치 매칭)은 "확인 필요"로 표시한다. 사용자가 확인하기 전에는 확정 방문으로 저장하지 않는다(명세 §7). 인식에 실패한 항목은 사용자가 직접 추가·수정할 수 있게 둔다.

## 사용자 콘텐츠(UGC)

- 팁 본문, 방명록, 이야기 같은 사용자 입력은 텍스트로만 렌더링한다. HTML·마크다운을 해석하지 않고, WebView에 넣지 않는다.
- 팁 반응(TIP-04, API-052)은 낙관적으로 반영할 수 있다. 실패하면 롤백하고, 집계 수는 서버 응답으로 교정한다.
- 팁 신고(TIP-12)는 명세상 P2다. 다만 사용자 생성 콘텐츠를 노출하는 앱은 스토어 심사에서 신고·차단 수단을 요구받을 수 있으므로, 출시 전에 범위를 다시 확인한다 `[확인]`.
- 팁 등록은 비동기 작업이다(API-049 작업 생성 → 상태 조회). 게시가 끝나기 전에는 "게시 중"으로 보여주고, 같은 팁이 두 번 등록되지 않게 막는다(멱등성 키, 규칙 90).

## 인증·세션

- 액세스·리프레시 토큰은 `expo-secure-store`에만 저장한다. AsyncStorage, Zustand persist, 로그에 저장하거나 출력하지 않는다.
- 소셜 로그인(구글·카카오, API-001·002·005)은 시스템 브라우저 기반 인증 세션으로 처리한다. 앱 안 WebView로 로그인 페이지를 띄우지 않는다. 콜백으로 돌아온 값은 검증한 뒤 토큰 발급을 요청한다.
- 로그아웃(MY-05)과 회원 탈퇴(MY-06) 시에는 토큰, Query 캐시, 업로드 대기열, 위치·카메라 관련 로컬 상태를 모두 지운다.
- 초대 링크(여행방 API-025, 기록 API-061)로 들어온 값은 검증한 뒤 참여 확인 화면을 거친다. 링크만으로 자동 참여시키지 않는다.
- 인증이 필요한 화면은 라우트 그룹(`app/(auth)`, `app/(app)`) 레이아웃에서 검사한다. 개별 화면에 흩어서 검사하지 않는다. 비회원 열람 범위(DEC-19)가 정해지기 전까지는 전 화면 로그인 필수로 둔다.

## 네트워크·키

- API 호출은 HTTPS만 사용한다.
- `EXPO_PUBLIC_` 환경 변수에는 API 베이스 URL처럼 공개 가능한 값만 둔다.
- 지도·AR SDK 키처럼 앱 번들에 들어가는 키는 추출될 수 있다고 간주한다. 공급자 콘솔에서 앱 패키지명·서명으로 사용을 제한한다(규칙 85).
