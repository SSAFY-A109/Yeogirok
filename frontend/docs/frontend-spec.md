# 여기록 프론트엔드 기능 명세

> **원천**: 팀 Notion "기능 명세서 v2"(버전 0.2, 2026-10-23 수정 — Figma 사용자 흐름 10/23 반영). 2026-10-27에 §3 화면 구성, §4 기능 목록 67개, §7 권한과 예외, §9 결정 필요 23개를 대조했다. API 연결은 Notion "API 명세" 목록(2026-10-27)과 기능 이름을 맞춰 본 프론트 쪽 대응이다 `[확인]`.
> 원천 문서가 진실이고 이 문서는 **프론트 관점 요약**이다. 둘이 다르면 원천이 이기고 이 문서를 고친다. `AGENTS.md`의 "명세에 없는 기능 추가 금지" 규칙에서 말하는 명세가 이 문서다.
> 우선순위: **P0** = 최종 시연의 핵심 흐름, **P1** = 시간이 되면 할 것(기술 포트폴리오 항목), **P2·P3** = 이후 과제. 화면·API는 P0부터 만들고, P1 이하는 요청이 있을 때만 만든다.

## 0. 서비스와 사용자

- **여기록** — 다른 사람의 여행 코스에서 원하는 장소를 가져와 내 일정을 만들고, 일행과 완성한 여행기를 다시 공유한다. 발자취는 개인의 방문 기록과 방문 통계에 쓰고, 현장에서 공유하는 경험 정보는 AR 팁으로 제공한다.
- **사용자 유형**: 소셜 로그인(구글·카카오) 회원 한 종류다. 역할 분기는 없다. 비회원 열람 범위는 DEC-19 결정 전까지 "없음"(전 화면 로그인 필수)으로 둔다.
- **플랫폼**: Android·iOS, 390pt 기준 디자인. 배포 방식은 `TBD`다.
- **데이터 원천**: 개발 환경에서는 MSW가 API 응답을 제공하고, 배포 환경에서는 실제 백엔드 API로 받는다(`docs/api-guide.md`). 요청·응답 형식은 팀 Notion "API 명세"와 Swagger를 따른다. 지도·AR SDK는 결정 전이다(규칙 85).
- **시연 시나리오(P0 최소 집합)**: 메인 페이지에서 코스 탐색 → 장소 선택 → 여행방에 담기 → AI 추천·검색으로 장소 추가 → 이동 수단 설정 → AI 일정 초안·조정 → (여행 중) 지도에서 발자취 남기기, AR 팁 보기·올리기 → (여행 후) 기록 만들기 → 사진·영수증 등록 → AI 기록 초안 확인 → 이야기 작성·완성 → 코스로 공개.

## 3. 이동 흐름

```
[계획]  메인 페이지 ─ 코스 상세 ─(장소 선택)─ 여행방 선택 시트 ─ 여행방 상세 ─(검색·AI 추천으로 추가)─ 이동 수단 ─ AI 일정 초안 ─ 일정 조정
[현장]  지도 탭 ─(위치 권한)─ 현재 위치 확인 ─ 방명록 작성·저장
        AR 팁 탭 ─(카메라 권한·AR 지원)─ 주변 팁 탐색 ─ 팁 상세·반응 / 나도 올리기 ─ 배치 ─ 본문·사진 ─ 공개 등록
[기록]  여행방 ─ 기록 만들기 ─ 사진·영수증 등록 ─ AI 기록 초안 ─ 초안 확인·수정 ─ 일정별 사진·이야기 ─ 여행기 완성 ─ 공개 미리보기 ─ 코스 공개
[순환]  공개된 코스 ─ 다른 사용자의 메인 페이지·코스 검색으로 다시 [계획]
```

초대 링크(여행방 API-025, 기록 API-061)는 딥링크로 들어온다. 로그인 → 참여 확인 화면 → 해당 여행방·기록 순서로 이동한다. 모르는 링크는 이동하지 않고 앱만 연다.

## 4. 화면 공통 상태 규칙

`AGENTS.md`의 완료 기준을 이 프로젝트 화면에 적용한 규칙이다. 화면마다 아래를 모두 구현해야 완성으로 본다.

| 상황 | 규칙 |
| --- | --- |
| 로딩 | `Skeleton`. 지도는 이전 영역 결과를 유지한 채 상단에 진행 표시 |
| 빈 상태 | 문구는 시안 확정 시 고정한다. 주변 팁 없음은 오류가 아닌 빈 상태로 보여주고 "나도 올리기"를 둔다(명세 §7) |
| 오류 | `ApiError.code`로 분기한다. 공통은 `api/errors.ts`, 도메인은 `features/<domain>/errors.ts`의 문구를 쓴다. 서버 `message`는 표시하지 않는다. 재시도 버튼을 둔다. 401은 토큰 갱신 후 1회 재시도하고, 실패하면 로그인으로 보낸다 |
| 권한 필요 | `PermissionGate`. 거부해도 입력 내용은 유지하고 대체 행동을 준다 |
| 처리 중(작업) | AI 초안·팁 게시는 단계 표시, 실패 시 재시도, 화면 이탈 후 복원(규칙 20) |
| 중복 실행 | 생성 요청(발자취·팁·초안·공개·초대 수락)은 `isPending` 동안 버튼 비활성 + 멱등성 키 |
| 오프라인·타임아웃 | 조회 10초, 변경 30초, 업로드 60초(`api/client.ts` 상수). 업로드는 실패한 파일만 재시도 |

## 5. 프론트가 지켜야 할 비즈니스 규칙

- 방문 분포도·방문 수·반응 수·영수증 합계·이동 시간·주차 정보는 서버 값만 표시하고 클라이언트에서 계산하지 않는다.
- 없는 이동·주차 정보는 "정보 없음"으로 구분한다. 0분이나 주차 가능 같은 확정값으로 채우지 않는다(명세 §7).
- 방명록 본문은 작성자 본인만 본다. 다른 사용자에게는 집계 통계만 보여준다(명세 §2).
- 방명록과 AR 팁은 별개다. 하나를 만들 때 다른 하나를 자동으로 만들지 않는다(DEC-06 기본값).
- AI 추출·추정 결과는 사용자 확인 전에 확정 방문으로 저장하지 않는다.
- 위치 권한 거부·확인 실패 시에는 발자취를 저장하지 않고, 방문 통계도 늘리지 않는다.
- 지역·카테고리 같은 선택지는 서버 기준 데이터(API-010·078·079)로 받고 하드코딩하지 않는다.
