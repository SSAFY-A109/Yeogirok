# 예외 처리, 로깅 및 보안 (React Native)

## 예외 처리

- 예외를 빈 `catch`로 무시하거나 `console.log`만 출력하고 종료하지 않는다.
- 단순히 화면에 기술적인 오류 메시지만 표시하지 않는다.
- 예상 가능한 오류와 예상하지 못한 오류를 구분해 처리한다.
- 사용자가 현재 상황을 이해하고 다음 행동을 수행할 수 있도록 오류를 처리한다.
- 입력 오류는 해당 필드 가까이에 원인과 해결 방법을 표시한다.
- 화면 또는 영역 오류는 오류가 발생한 범위에서 복구 방법과 함께 표시한다.
- 재시도로 해결될 수 있는 오류에는 재시도 수단을 제공하되 중복 요청이 발생하지 않도록 한다.
- 오류 발생 후에도 사용자가 입력한 값과 작업 맥락을 가능한 한 유지한다.
- 렌더링 오류는 적절한 범위의 Error Boundary로 격리한다. Expo Router에서는 라우트 파일의 `ErrorBoundary` export를 활용할 수 있다.

## 오류 상황별 기본 대응

- 비로그인 상태에서는 로그인 화면으로 이동하고 로그인 후 기존 화면으로 복귀할 수 있도록 한다.
- 권한 부족 시 접근 불가를 안내하고 사용자가 접근 가능한 안전한 화면으로 이동할 수 있도록 한다.
- API 요청 실패 시 사용자 친화적인 안내와 재시도 수단을 제공한다.
- 모바일 환경 특성상 오프라인과 불안정한 연결이 흔하므로 네트워크 오류 시 연결 상태와 재시도 방법을 안내한다.
- 데이터가 없을 경우 빈 화면 대신 의미 있는 빈 상태 UI를 표시한다.
- 저장 실패 시 입력값을 유지한 채 재시도할 수 있도록 한다.
- 일부 데이터만 실패한 경우 전체 화면을 막지 않고 실패한 영역에 대체 UI를 제공한다.

## 로깅

- 오류 수집 도구가 설정되어 있다면 개인정보, 인증 정보, 요청 본문을 제거한 뒤 필요한 문맥과 함께 기록한다.
- 사용자에게 내부 오류 메시지, 서버 스택 트레이스, 토큰, 요청 헤더를 노출하지 않는다.
- 인증 토큰, 개인정보, API 응답 전체를 콘솔이나 오류 메시지에 출력하지 않는다.

## 보안 및 환경 변수

- `EXPO_PUBLIC_` 접두사가 붙은 환경 변수는 앱 번들에 노출된다고 간주한다.
- `EXPO_PUBLIC_` 환경 변수와 `app.json`의 `extra`에 비밀번호, 비밀 키, 서버 전용 토큰을 저장하지 않는다.
- 인증 토큰 등 민감한 값은 AsyncStorage가 아니라 `expo-secure-store`에 저장한다.
- 딥링크와 라우트 파라미터로 전달된 값은 신뢰하지 않고 검증 후 사용한다.
- WebView에 신뢰할 수 없는 HTML이나 사용자 입력을 직접 주입하지 않는다.
- 클라이언트의 권한 검사는 UX 보조 수단으로만 사용하고 보안이 클라이언트 검사만으로 보장된다고 가정하지 않는다.
