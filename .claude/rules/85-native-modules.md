# 네이티브 모듈 (지도·AR·카메라·위치)

여기록의 지도(발자취 분포도·경로), AR 팁, 카메라·사진, 현재 위치 기능은 네이티브 모듈을 쓴다. 이 규칙은 그 모듈을 들이고 쓰는 방식을 정한다. 위치·사진의 공개 범위와 보안은 규칙 80을 따른다.

## 빌드 전제 — Expo는 그대로 쓴다

- Expo SDK와 Expo Router는 그대로 쓴다. 제약은 **Expo Go 앱**에만 있다. Expo Go에는 미리 들어간 네이티브 모듈만 있어서, AR이나 일부 지도 SDK처럼 추가 네이티브 코드가 필요한 모듈은 Expo Go에서 동작하지 않는다.
- 그래서 이 모듈들은 **개발 빌드**(`expo-dev-client` + `expo prebuild` 또는 EAS Build)에서 실행한다. 개발 빌드는 이 프로젝트 전용 Expo 앱을 한 번 빌드해 설치하는 것이다. 빌드한 뒤에는 Expo Go처럼 `expo start`로 JS를 바로 반영한다. 네이티브 모듈이나 config plugin을 바꿨을 때만 다시 빌드한다.
- Expo Go는 네이티브 모듈을 쓰지 않는 화면의 UI 확인용으로만 쓴다.
- 네이티브 설정은 `app.json`(또는 `app.config.ts`)의 config plugin으로만 바꾼다. `/ios`, `/android`는 생성물(`.gitignore`)이므로 직접 수정하지 않는다.
- 권한 설명 문구는 config plugin 옵션에 한국어로 쓰고, 어떤 기능에 쓰는지 구체적으로 적는다.
  - iOS: `NSLocationWhenInUseUsageDescription`, `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`
  - Android: 위치·카메라 권한
- 네이티브 모듈 설치와 config plugin 추가는 승인 후 `pnpm expo install`로 한다. 보고에는 "개발 빌드 재생성 필요"를 적는다.

## 모듈 선택

결정 필요 항목은 결정 전까지 임의로 고르거나 설치하지 않는다. 화면은 아래 "모듈 경계"의 어댑터를 거쳐 쓰므로, 결정 전에도 어댑터 인터페이스와 목 구현으로 화면을 만들 수 있다.

| 용도 | 기본값 | 상태 |
| --- | --- | --- |
| 현재 위치 | `expo-location` (foreground 전용) | 설치 시 승인 |
| 카메라·사진 선택 | `expo-camera`, `expo-image-picker` | 설치 시 승인 |
| 사진 메타데이터 제거·리사이즈 | 재인코딩 방식(`expo-image-manipulator` 등) — 제거 여부는 실기기에서 EXIF 확인 | 설치 시 승인 `[확인]` |
| 지도 SDK | 국내 지도 데이터, 마커 클러스터, 경로선 지원으로 비교. 이동 시간·주차 정보는 서버가 계산(DEC-14)하므로 클라이언트 길찾기 API는 쓰지 않는다 | 결정 필요 |
| AR | 지원 범위와 공간 저장 방식(DEC-08) 결정 후 선택. 후보 예: ViroReact(Expo 프로젝트 지원, 위치 고정·공유 앵커는 자체 플랫폼 키 필요) | 결정 필요 |

## 모듈 경계

- 네이티브 SDK는 어댑터 한 곳에서만 import한다. 화면과 다른 도메인 코드는 어댑터가 내보내는 훅·컴포넌트만 쓴다. 지도·AR SDK가 미정이거나 교체될 수 있기 때문이다.
  - 도메인 공용 어댑터: `lib/native/location.ts`, `lib/native/map/`, `lib/native/camera.ts`
  - AR처럼 한 도메인에서만 쓰는 어댑터: `features/tip/native/ar/`
- 지도 경로·핀·발자취 색은 className이 닿지 않는다. `lib/theme.ts`의 `getColors()["map-route" | "map-pin" | "map-footprint"]`로 넘기고, hex를 쓰지 않는다.
- 발자취 핀(`map-footprint`, 흰 지도 대비 1.84:1)에는 흰 테두리를, 경로선에는 3px 이상 두께를 준다(DESIGN.md §2 대비 주의).
- 지도 영역을 옮기는 이벤트로 바로 API를 부르지 않는다. 이동이 멈춘 뒤 디바운스하고, 화면 영역을 쿼리 키로 조회한다(규칙 20 화면 영역 조회).
- 마커는 서버가 집계한 단위로 그린다. 개수가 많으면 클러스터로 묶는다.

## 위치 구독

- 현재 위치는 필요한 순간에 한 번 측정(`getCurrentPositionAsync`)하는 것을 기본으로 한다. 계속 구독(`watchPositionAsync`)해야 하는 화면(AR 팁 탐색 등)은 화면이 보이는 동안만 구독하고, 화면을 벗어나거나 앱이 백그라운드로 가면 해제한다.
- 측정 결과에는 정확도와 측정 시각을 함께 보관한다. 이 값이 위치 증거로 쓰인다(규칙 80).

## AR

- AR 화면에 들어가기 전에 다음을 확인한다.
  - 기기 지원 여부와 카메라 권한을 확인한다.
  - 미지원이나 권한 거부일 때는 이유와 다음 행동을 안내한다(명세 §7). 예: 지도에서 주변 팁 위치 보기.
  - 발자취·여행 계획·기록 기능은 AR 상태와 분리해 둔다. AR이 안 돼도 이 기능들은 동작한다.
- 화면에 표시할 상태
  - 추적 상태(초기화 중, 불안정, 조명 부족)를 보여준다.
  - 공간 위치 복원 실패(TIP-10)는 "주변 팁 없음"과 구분해서 보여준다.
  - 재탐색·대체 보기 정책은 결정 필요다.
- AR 세션은 화면을 벗어나거나 탭을 바꾸거나 앱이 백그라운드로 가면 즉시 멈추고, 카메라를 해제한다. 카메라·AR 화면은 동시에 하나만 활성화한다.
- 클라우드 앵커 같은 외부 공간 저장 서비스는 정책 변경이나 종료 공지가 있을 수 있다. 앵커 id만 저장할지, 좌표·방위 같은 대체 복원 정보를 함께 저장할지는 계약에서 정한다(`TBD`, DEC-08).

## 키 관리

- 지도·AR SDK 키는 앱 번들에 들어가면 추출될 수 있다. 앱에는 공개용 키만 둔다. 공급자 콘솔에서 패키지명·번들 id·서명 해시로 사용을 제한한다.
- 비밀 키가 필요한 호출(서버 측 앵커 호스팅, 경로·주차 조회 등)은 백엔드가 대행한다. 비밀 키를 `EXPO_PUBLIC_` 변수나 `app.json`의 `extra`에 두지 않는다(규칙 50).

## 검증과 보고

- 네이티브 모듈이 걸린 변경은 실기기(최소 Android 1대) 확인 여부와 결과를 보고한다. 시뮬레이터·에뮬레이터에서는 AR과 카메라를 검증할 수 없다.
- E2E(Maestro)는 개발 빌드나 E2E용 빌드로 실행한다(규칙 60). AR 카메라 화면 자체는 자동화하지 않고, 권한 거부·미지원 폴백 경로만 자동화한다.
- 보고에는 다음을 적는다.
  - 새로 들인 네이티브 모듈과 config plugin 변경
  - 개발 빌드 재생성 필요 여부
  - 실기기 확인 결과(미확인이면 "미확인")
