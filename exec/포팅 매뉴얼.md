## 1. 프로젝트 개요

여기록은 다른 사람이 다녀온 여행 코스와 발자취에서 원하는 장소를 가져와 일행과 여행방에서 일정을 짜고, 다녀온 뒤 일행의 사진과 영수증으로 함께 여행기를 만들어 다시 코스로 공개하는 여행 코스 공유 서비스이다. Android 앱은 HTTPS로 메인 API만 호출한다. 영수증 OCR 서버는 바깥에 열지 않고 메인 API가 서버 내부망으로만 부른다. 테이블은 메인 API의 Flyway 마이그레이션만 만든다.

저장소는 모노레포이고, 파트마다 자기 `<part>/dev` 브랜치에서 관리한다. 서버에도 브랜치별로 따로 받는다.

```text
Yeogirok/
├─ frontend/   Android 앱 (React Native · Expo)            frontend/dev
├─ backend/    메인 API (Spring Boot)                      backend/dev
├─ ai/ocr/     영수증 OCR 서버 (FastAPI · PaddleOCR)       ai/dev
├─ infra/      서버 Compose · Nginx · 배포 스크립트 · Jenkins  infra/dev
└─ docs/       공통 컨벤션                                 main
```

```text
[Android 앱] ──HTTPS·WSS──▶ [Nginx 80·443] ──▶ [backend 127.0.0.1:8080] ──▶ [db PostgreSQL+PostGIS]
     │                                              │                   ──▶ [redis]
     │                                              ├─ 내부망 http://ai:8000 ──▶ [ai 영수증 OCR]
     │                                              └─ 외부 API: 구글·카카오 OIDC, 카카오 로컬·모빌리티, TourAPI, FCM, S3
     ├─ Presigned URL ──▶ AWS S3 (사진·영수증 직접 업로드·다운로드)
     └─ 카카오맵 JavaScript API(WebView), ARCore
```

## 3. 서버 구성

### 3.1 개요

- 서버 한 대(AWS EC2, Ubuntu)에 Docker Compose 프로젝트 두 개를 띄운다.
  - `yeogirok` (`infra/docker-compose.yml`): `db`, `redis`, `backend`, `ai`
  - `yeogirok-jenkins` (`infra/jenkins/docker-compose.yml`): `jenkins`. 앱과 따로 켜고 끈다.
- Nginx와 certbot은 컨테이너가 아니라 서버에 직접 설치한다.
- 바깥에서 들어오는 길은 Nginx(80·443) 하나이다. 컨테이너 포트는 모두 `127.0.0.1:`에만 연다. Docker는 ufw 규칙을 건너뛰고 포트를 열기 때문에, `127.0.0.1:`을 지우면 DB가 인터넷에 노출된다.
- 열어야 할 포트(AWS 보안 그룹·ufw): 22(SSH), 80(HTTP), 443(HTTPS).
- 도메인: `k15a109.p.ssafy.io` (HTTPS, Let's Encrypt).
- 파일에 기록된 서버 사양: CPU 4코어(`infra/README.md` 9단계 표), 메모리 15GB(`infra/jenkins/docker-compose.yml` 주석). 메모리가 8GB 이하면 스왑 4GB를 더한다(5.2).

### 3.2 컨테이너

| 서비스 | 이미지 | 호스트 포트 | 볼륨 | 비고 |
| --- | --- | --- | --- | --- |
| `db` | `postgis/postgis:16-3.4` | `127.0.0.1:5432` | `db-data` | `pg_isready` 헬스체크, `TZ=Asia/Seoul` |
| `redis` | `redis:7.4-alpine` | 열지 않음 (내부 `redis:6379`) | `redis-data` | `--requirepass`, AOF(`appendonly yes`), `maxmemory 256mb`, `noeviction` |
| `backend` | `yeogirok-backend:latest` (`~/yeogirok/backend-src/backend`의 `Dockerfile`로 빌드) | `127.0.0.1:8080` | — | `SPRING_PROFILES_ACTIVE=prod`. db·redis가 healthy가 된 뒤 뜬다. 이미지 라벨 `yeogirok.commit` |
| `ai` | `yeogirok-ai:latest` (`~/yeogirok/ai-src/ai/ocr`의 `Dockerfile`로 빌드) | 열지 않음 (내부 `ai:8000`) | `ai-models:/home/app/.paddlex` | CPU 실행, `mem_limit: 3g`, `/health` 헬스체크(`start_period 120s`). OCR 모델(약 100MB)은 처음 켤 때 받는다 |
| `jenkins` | `jenkins/jenkins:lts-jdk21` | `127.0.0.1:9090` → 컨테이너 8080 | `jenkins-home`, `/var/run/docker.sock` | `JENKINS_OPTS=--prefix=/jenkins`, `mem_limit: 4g`, `host.docker.internal:host-gateway` |

- 백엔드 이미지는 JDK로 bootJar를 만든 뒤 JRE 이미지에 담고, root가 아닌 `app` 사용자로 실행한다. 이미지에 비밀 값을 넣지 않는다(`.dockerignore`가 `.env`를 뺀다).
- AI 이미지는 `requirements.txt`의 `paddlepaddle-gpu`를 CPU용 `paddlepaddle==3.2.2`로 바꾸고 `mlflow`·`matplotlib`를 빼서 설치한다. `.dockerignore`는 허용 목록 방식이라 실제 영수증 사진이 이미지에 들어가지 않는다.
- Jenkins는 서버 Docker(`docker.sock`)를 쓰므로 Jenkins 관리자 권한이 곧 서버 root 권한이다. 계정은 꼭 필요한 사람에게만 만든다.

### 3.3 Nginx 경로

`infra/nginx/yeogirok.conf`는 서버의 `/etc/nginx/sites-available/yeogirok`, `infra/nginx/jenkins.conf`는 `/etc/nginx/snippets/yeogirok-jenkins.conf`로 복사해 쓴다.

| 경로 | 넘기는 곳 | 설정 |
| --- | --- | --- |
| `/` | backend `127.0.0.1:8080` | `Host`·`X-Real-IP`·`X-Forwarded-For`·`X-Forwarded-Proto` 전달, `proxy_read_timeout 120s`, `client_max_body_size 20m` |
| `/ws/` | backend `127.0.0.1:8080` (채팅 `wss://<도메인>/ws/v1`) | HTTP/1.1, `Upgrade`·`Connection` 헤더, read·send timeout 75s (앱 PING 25초, 백엔드 무응답 종료 60초보다 길게) |
| `= /jenkins` | `301 /jenkins/` | |
| `= /jenkins/generic-webhook-trigger/invoke` | Jenkins `127.0.0.1:9090` | POST만, 어디서나 허용. 주소 끝 토큰이 맞아야 빌드가 돈다 |
| `/jenkins/cli` | — | `deny all` |
| `/jenkins/` | Jenkins `127.0.0.1:9090` | 허용 IP 목록(서버에만 두는 `/etc/nginx/snippets/yeogirok-jenkins-allow.conf`)만 허용, 나머지 403 |

백엔드가 응답하는 주요 주소

| 주소 | 내용 |
| --- | --- |
| `https://<도메인>/api/v1/...` | 앱 API |
| `https://<도메인>/swagger-ui.html`, `/v3/api-docs` | API 문서. 배포 스크립트는 `http://127.0.0.1:8080/v3/api-docs`로 응답을 확인한다 |
| `wss://<도메인>/ws/v1` | 채팅 WebSocket |
| `https://<도메인>/.well-known/assetlinks.json` | Android App Links (초대 링크를 앱으로 연다) |
| `https://<도메인>/invite/...` | 여행방 초대 링크 (`ROOM_INVITE_URL_BASE` 뒤에 `/{초대 토큰}`) |

## 4. 환경 변수

`.env`는 커밋하지 않는다(공개 저장소). 노션에도 키 이름과 발급처만 적고 값은 적지 않는다. 비밀 값은 명령 기록에 남지 않게 `read -rs`로 입력한다(5.3).

### 4.1 서버 `infra/.env` (`~/yeogirok/infra-src/infra/.env`, `infra/.env.example` 기준)

| 변수 이름 | 설명 | 필수 여부 | 예시/기본값 |
| --- | --- | --- | --- |
| `DB_NAME` | DB 이름 | 필수 | `yeogirok` |
| `DB_USERNAME` | DB 계정 | 필수 | `yeogirok` |
| `DB_PASSWORD` | DB 비밀번호. DB 볼륨을 처음 만들 때만 적용된다. 나중에 바꾸려면 볼륨을 지우고 다시 만든다 | 필수 | 직접 생성: `openssl rand -hex 24` (AI가 DB 주소에 넣을 수 있어 `-base64` 대신 `-hex`) |
| `REDIS_PASSWORD` | Redis 비밀번호. 없으면 모든 `docker compose` 명령이 `required variable REDIS_PASSWORD is missing a value`로 멈춘다 | 필수 | 직접 생성: `openssl rand -hex 24` (DB와 다른 값) |
| `AWS_REGION` | S3 리전 | 필수 (없으면 백엔드 기동 실패) | `ap-northeast-2` |
| `S3_PHOTO_BUCKET` | 사진 버킷 | 필수 | `yeogirok-a109-photos-prod` |
| `S3_RECEIPT_BUCKET` | 영수증 버킷. 사진 버킷과 달라야 한다(영수증 정리 작업이 버킷 전체를 지운다) | 필수 | `yeogirok-a109-receipts-prod` |
| `AWS_ACCESS_KEY_ID` | 서버 전용 IAM 사용자의 접근 키 | 기능상 필수 (없어도 뜨지만 업로드·정리 작업·공식 코스 적재가 실패) | 직접 발급 |
| `AWS_SECRET_ACCESS_KEY` | 위 접근 키의 비밀 키 | 위와 같음 | 직접 발급 |

3. 서버에서 `git -C ~/yeogirok/infra-src pull && docker compose up -d backend`를 실행한다.

## 5. 빌드·배포 방법

순서: 5.1~5.5 서버 처음 설치 → 5.6 Jenkins 자동 배포 → 5.7~5.10 운영 → 5.11 로컬 개발 → 5.12 Android 앱.

### 5.1 준비물

- 서버 접속 정보(키 파일, 계정), 서버에 연결된 도메인. HTTPS 인증서는 IP가 아니라 도메인에 발급된다.
- AWS 보안 그룹에서 22·80·443이 열려 있어야 한다. 막혀 있으면 HTTPS 발급과 배포가 실패한다.
- 6장의 외부 서비스 키.

### 5.2 서버 기본 세팅

```bash
chmod 400 <키파일>.pem
ssh -i <키파일>.pem <서버 계정>@<도메인>

lsb_release -ds      # Ubuntu 버전
nproc                # CPU 개수
free -h              # 메모리
df -h /              # 디스크

sudo timedatectl set-timezone Asia/Seoul
sudo apt-get update && sudo apt-get -y upgrade
```

메모리가 8GB 이하이면 스왑을 만든다. Gradle 빌드와 OCR이 메모리를 많이 써서 모자라면 `Killed`로 멈춘다.

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # 재부팅 후에도 유지
free -h                                                      # Swap 4.0Gi 확인
```

Docker를 공식 저장소로 설치한다.

```bash
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo usermod -aG docker $USER   # sudo 없이 docker 쓰기
exit                            # 다시 접속해야 적용된다
```

다시 접속한 뒤 확인한다.

```bash
docker run --rm hello-world     # "Hello from Docker!" 가 나오면 성공
docker compose version
sudo ufw status                 # active 이면: sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
```

22번(SSH)을 막는 ufw 명령은 쓰지 않는다. 접속이 끊기면 다시 들어올 방법이 없다.

### 5.3 코드 받기와 `.env`

공개 저장소라 로그인 없이 받는다. `ai-src`가 없으면 서비스 이름 없는 `docker compose up -d`가 ai를 빌드하지 못해 멈춘다.

```bash
mkdir -p ~/yeogirok && cd ~/yeogirok
git clone --single-branch --branch infra/dev   https://github.com/SSAFY-A109/Yeogirok.git infra-src
git clone --single-branch --branch backend/dev https://github.com/SSAFY-A109/Yeogirok.git backend-src
git clone --single-branch --branch ai/dev      https://github.com/SSAFY-A109/Yeogirok.git ai-src
```

비밀 값 파일을 만든다. 각 값의 뜻은 4.1을 본다.

```bash
cd ~/yeogirok/infra-src/infra
cp .env.example .env
openssl rand -hex 24         # 나온 값을 DB_PASSWORD 에 넣는다
openssl rand -hex 24         # 한 번 더 만들어 다른 값을 REDIS_PASSWORD 에 넣는다
openssl rand -base64 48      # JWT_SECRET 에 넣는다 (이것만 base64)
openssl rand 64 | base64 -w0 # ROOM_INVITE_TOKEN_KEY 에 넣는다 (88자 한 줄)
nano .env                    # 위 값과 4.1 의 나머지 값을 채운다. 저장: Ctrl+O, Enter / 나가기: Ctrl+X
chmod 600 .env               # 나만 읽을 수 있게
```

외부 서비스 키처럼 화면과 명령 기록에 남기고 싶지 않은 값은 다음 함수로 넣는다.

```bash
setenv() { sed -i "/^$1=/d" .env; printf '\n%s=%s\n' "$1" "$2" >> .env; }   # 같은 키가 두 번 들어가지 않게 지우고 새로 쓴다
read -rsp 'GOOGLE_WEB_CLIENT_SECRET: ' v && setenv GOOGLE_WEB_CLIENT_SECRET "$v"; echo
```

빠진 값을 확인한다. `docker compose config`는 `.env`에 **없는** 값만 알려 주고, `KEY=`처럼 **비어 있는** 값은 알려 주지 않아 `grep`으로 따로 본다.

```bash
docker compose config -q 2>&1 | grep 'not set'    # .env 에 없는 값 목록
grep -E '^[A-Z0-9_]+=$' .env                      # 값이 비어 있는 키 목록 (선택 키만 남으면 된다)
```

### 5.6 자동 배포 (Jenkins)

흐름: `backend/dev`에 push(머지) → GitHub 웹훅 → Nginx `/jenkins/generic-webhook-trigger/invoke` → Jenkins job `yeogirok-backend` → ① `backend/dev` 체크아웃 → ② `./gradlew --no-daemon test` → ③ SSH로 서버에 들어가 `DEPLOY_SHA=<테스트한 커밋> bash ~/yeogirok/infra-src/infra/scripts/deploy-backend.sh` → ④ Mattermost 알림, GitHub 커밋 상태 `jenkins/backend`.

- 파이프라인 파일은 `infra/dev`의 `infra/jenkins/backend.Jenkinsfile`이다. Jenkins가 빌드할 때마다 새로 읽는다.
- 웹훅은 모든 브랜치 push로 오지만 `refs/heads/backend/dev`일 때만 빌드한다.
- 배포 스크립트는 서버의 infra 코드를 받아 오지 않는다. compose·Nginx가 바뀌면 손으로 반영한다(5.7).
- AI 서버는 자동 배포가 없다(5.7).

**① Jenkins 켜기** (`git pull`은 앱 compose 변경도 함께 받으므로 4.1의 `.env` 값이 다 있는지 먼저 확인한다)

```bash
cd ~/yeogirok/infra-src && git pull
cd infra/jenkins
echo "DOCKER_GID=$(getent group docker | cut -d: -f3)" > .env
cat .env                    # DOCKER_GID=숫자 한 줄이면 정상
docker compose up -d
docker compose logs -f      # "Jenkins is fully up and running" 이 보이면 Ctrl+C
```

**② Nginx에 `/jenkins/` 연결** (certbot이 고친 서버 파일은 덮어쓰지 않고 `include` 한 줄만 넣는다)

```bash
CONF=/etc/nginx/sites-available/yeogirok
sudo cp $CONF ~/nginx-yeogirok.bak
SNIP=/etc/nginx/snippets/yeogirok-jenkins.conf
sudo cp ~/yeogirok/infra-src/infra/nginx/jenkins.conf $SNIP
ALLOW=/etc/nginx/snippets/yeogirok-jenkins-allow.conf
MYIP=${SSH_CLIENT%% *}
echo $MYIP                          # 내 노트북의 바깥 IP
echo "allow $MYIP;   # $(date +%F) 인프라 담당" | sudo tee $ALLOW
grep -c 'location / {' $CONF        # 1 이어야 한다
sudo sed -i '/location \/ {/i include snippets/yeogirok-jenkins.conf;' $CONF
grep -n 'include snippets' $CONF    # 한 줄 보이면 정상
sudo nginx -t                       # "syntax is ok"
sudo systemctl reload nginx
```

- 허용 IP 목록은 공개 저장소에 올리지 않고 서버에만 둔다(예시: `infra/nginx/jenkins-allow.conf.example`). 목록 밖에서는 403이 정상이다.
- 목록 밖에서 열 때는 SSH 터널을 쓴다: `ssh -i <키파일>.pem -L 9090:127.0.0.1:9090 <서버 계정>@<도메인>` 후 `http://localhost:9090/jenkins/`.

**③ 처음 설정 (브라우저 `https://<도메인>/jenkins/`)**

```bash
cd ~/yeogirok/infra-src/infra/jenkins
docker compose exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword   # 잠금 해제 비밀번호
```

2. Create First Admin User. 비밀번호는 길게 만든다(`openssl rand -base64 18`).
3. Instance Configuration의 Jenkins URL: `https://<도메인>/jenkins/`.
4. Manage Jenkins → Plugins → Available plugins에서 `Generic Webhook Trigger`를 설치한다.
5. Manage Jenkins → Security: Jenkins' own user database에서 Allow users to sign up 끄기, Logged-in users can do anything에서 Allow anonymous read access 끄기.

```bash
cat ~/jenkins_key           # 출력 전체를 server-ssh 의 Private Key 에 붙여 넣는다
```

### 5.7 수동 배포·되돌리기·운영 명령

모두 서버의 `~/yeogirok/infra-src/infra`에서 실행한다.

`deploy-backend.sh`의 안전장치와 끝나는 코드

| 단계 | 하는 일 |
| --- | --- |
| 배포 전 점검 | 새 커밋의 `application*.yaml`이 기본값 없이 요구하는 값을 compose·`.env`가 넘기는지 `check-backend-env.sh`로 본다. 빠지면 아무것도 바꾸지 않고 끝난다 |
| 되돌릴 이미지 표시 | 지금 백엔드가 정상 응답하면 그 이미지에 `yeogirok-backend:previous`를 붙인다 |
| 빌드 | `docker compose build backend`. 실패하면 기존 컨테이너가 그대로 남는다 |
| 교체·확인 | `http://127.0.0.1:8080/v3/api-docs`가 120초 안에 응답해야 성공. 재시작이 2번 이상 반복되면 실패로 본다 |
| 자동 되돌리기 | 실패하면 `previous` 이미지로 되돌린다(코드만, DB는 되돌리지 않음) |

| 코드 | 뜻 |
| --- | --- |
| 0 | 성공 |
| 1 | 그 밖의 실패(빌드 실패, 되돌릴 이미지 없음, 되돌리기 실패) |

| 3 | 새 버전이 뜨지 않아 이전 버전으로 되돌림 |

### 5.8 DB 마이그레이션 (Flyway)

- 백엔드가 뜰 때 Flyway가 `backend/src/main/resources/db/migration`의 새 파일을 자동으로 적용한다. 따로 실행할 명령은 없다.
- `local`·`prod` 프로필은 `ddl-auto: validate`이다. 엔티티와 테이블이 맞지 않으면 백엔드가 뜨지 않는다.
- 스키마를 바꿀 때: 엔티티 수정 → 다음 번호 파일 `V{번호}__{설명}.sql`(PostgreSQL 문법) 추가 → 로컬 PostgreSQL에서 `./gradlew bootRun`으로 적용·검증.
- 한 번 적용된 파일은 고치지 않는다(`checksum mismatch`로 시작 거부). 번호는 `backend/dev`에 머지된 마지막 번호 다음을 쓴다.
- 테스트는 H2를 쓰고 Flyway를 끈다. 테스트로는 마이그레이션 파일이 검증되지 않는다.
- 컬럼을 지우거나 이름을 바꾸는 마이그레이션 뒤에는 이전 이미지로 되돌려도 뜨지 못할 수 있다. 그런 PR은 배포 시간을 맞춘다.

적용 기록 확인

```bash
cd ~/yeogirok/infra-src/infra
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select version, description, success from flyway_schema_history"'
```

Flyway 이전(`ddl-auto: update`)에 만든 테이블이 남은 DB는 `Found non-empty schema(s) "public" but no schema history table`로 시작을 거부한다. 이때만 DB를 비운다(데이터가 지워진다).

```bash
cd ~/yeogirok/infra-src/infra
bash scripts/backup-db.sh                      # 혹시 모르니 백업
docker compose stop backend
docker compose rm -sf db
docker volume rm yeogirok_db-data              # DB 데이터 삭제
docker compose up -d db
bash scripts/deploy-backend.sh                 # 새 코드로 백엔드 띄우기 (이때 마이그레이션 적용)
```

로컬 DB 비우기: `docker compose -f infra/docker-compose.local.yml down -v && docker compose -f infra/docker-compose.local.yml up -d`

### 5.9 백업·복구

```bash
bash ~/yeogirok/infra-src/infra/scripts/backup-db.sh    # 지금 한 번. "[backup] ... (크기)" 가 나오면 성공
ls -lh ~/yeogirok/backups

crontab -e
# 매일 새벽 4시 백업, 7일 지난 백업 자동 삭제
0 4 * * * bash $HOME/yeogirok/infra-src/infra/scripts/backup-db.sh >> $HOME/yeogirok/backup.log 2>&1
```

- 백업 파일: `~/yeogirok/backups/yeogirok-YYYY-MM-DD-HHMMSS.sql.gz` (`pg_dump` + gzip). 보관 기간은 `KEEP_DAYS`(기본 7일).
- 실패하면 파일을 남기지 않고, 오래된 백업은 새 백업이 성공했을 때만 지운다. 다음 날 `tail ~/yeogirok/backup.log`에 `실패:` 줄이 없는지 본다.

복구 (지금 DB 내용이 모두 백업 시점으로 바뀌고, 그동안 백엔드가 멈춘다)

```bash
cd ~/yeogirok/infra-src/infra
ls -lh ~/yeogirok/backups                                   # 되돌릴 파일 고르기
bash scripts/restore-db.sh ~/yeogirok/backups/<파일>.sql.gz  # restore 를 입력하면 시작
```

- 순서: 지금 상태 백업 → 백엔드 멈춤 → DB를 지우고 새로 만듦 → 백업 붓기(`ON_ERROR_STOP`) → 백엔드 켜고 응답 확인.
- 백업 파일을 지금 DB에 그냥 부으면 `already exists` 오류만 나고 데이터는 돌아오지 않는다. 반드시 `restore-db.sh`를 쓴다.
- S3 파일과 Redis는 이 백업에 들어가지 않는다.

### 5.10 (선택) 투어API 공식 코스 적재

투어API 여행코스를 공식 계정의 공개 코스로 넣는 일회성 작업이다. `COURSE_SEED_ENABLED=true`일 때만 백엔드가 뜬 뒤 한 번 돈다. 적재 파일(묶음)은 사진 버킷의 `course-seed/` 아래에 있어야 하고, 서버 `.env`에 S3 접근 키가 있어야 한다. 묶음 파일은 저장소에 없고 `backend/tools/tour-course-fetch`(Python 3.12 표준 라이브러리, `TOUR_API_KEY`·`KAKAO_REST_API_KEY` 사용)로 만든다.

```bash
cd ~/yeogirok/infra-src/infra
grep -cE '^AWS_(ACCESS_KEY_ID|SECRET_ACCESS_KEY)=.+' .env   # 2 여야 한다
grep -E '^S3_(PHOTO|RECEIPT)_BUCKET=' .env         # 두 버킷 이름이 달라야 한다
setenv() { sed -i "/^$1=/d" .env; printf '\n%s=%s\n' "$1" "$2" >> .env; }
```

### 6.1 카카오 Developers

로그인 (`backend/docs/05-social-login-setup.md` 3절)

1. 앱 설정 → 앱 → 플랫폼 키 → 네이티브 앱 키 → `Default Native AppKey` ⋮ → 수정
   - 패키지명: `com.ssafya109.yeogirok`
   - 키 해시: 앱을 서명하는 키마다 하나씩 추가(디버그·배포)
2. 제품 설정 → 카카오 로그인 → 사용 설정 ON (꺼져 있으면 `KOE004`), OpenID Connect ON (꺼져 있으면 ID 토큰이 나오지 않는다)
3. 동의항목: 닉네임 필수, 프로필 사진 선택, 카카오계정(이메일) 선택
4. 네이티브 SDK 로그인에는 리다이렉트 URI가 필요 없다.
5. 처음 한 번 실제 ID 토큰의 `aud`를 디코드해 `KAKAO_APP_KEY`와 같은지 본다. 다르면 서버 로그에 `audience 불일치`가 남는다.

```bash
# 키 해시 (로컬 개발 빌드의 debug.keystore. 비밀번호 android 는 Android 기본 디버그 키 값)
keytool -exportcert -alias androiddebugkey -keystore frontend/android/app/debug.keystore -storepass android | openssl sha1 -binary | openssl base64
# 다른 키의 SHA-1(AA:BB:…)을 키 해시로 바꾸기
echo AA:BB:… | tr -d ':' | xxd -r -p | openssl base64
# ID 토큰의 aud 확인
echo '<ID 토큰의 두 번째 . 사이 문자열>' | tr '_-' '/+' | base64 -d 2>/dev/null; echo
```

- 어드민 키는 서버 밖으로 내보내지 않는다. 호출 허용 IP 주소에 서버 IP를 등록한다.

지도 (`frontend/docs/kakao-map-test.md`)

- 앱 → 플랫폼 키 → JavaScript 키를 복사하고, JavaScript 키 수정 화면의 JavaScript SDK 도메인에 `https://localhost`를 **포트 없이** 등록한다. Android 배포 빌드는 평문 HTTP를 막아 HTTPS를 쓴다.
- 앱에 넣은 키와 도메인을 등록한 키가 같은지 확인한다. 네이티브 앱 키·패키지명·키 해시는 지도에는 필요 없다.
- PC에서 등록 확인(200 통과, 401 거부):

```bash
curl -s -o /dev/null -w "%{http_code}\n" -H "Referer: https://localhost/" "https://dapi.kakao.com/v2/maps/sdk.js?autoload=false&appkey=<JavaScript 키>"
```

- 확인 필요: `frontend/.env.example` 주석은 "웹 플랫폼에 http://localhost 등록"이라고 적혀 있어 위 문서(`https://localhost`)와 다르다. 이 매뉴얼은 문서 쪽을 따랐다.

### 6.2 Google Cloud

로그인 (`backend/docs/05-social-login-setup.md` 2절)

1. 팀 프로젝트 → Google 인증 플랫폼(OAuth 동의 화면): 대상 외부, 범위 `openid`·`email`·`profile`. 게시 상태가 테스트인 동안에는 테스트 사용자로 등록한 계정만 로그인된다.
2. OAuth 클라이언트 ID ① 웹 애플리케이션: 승인된 JavaScript 원본·리디렉션 URI는 비운다. 클라이언트 ID는 서버 `GOOGLE_WEB_CLIENT_ID`와 앱 `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`에, secret은 서버 `GOOGLE_WEB_CLIENT_SECRET`에만 넣는다.
3. OAuth 클라이언트 ID ② Android: 패키지 이름 `com.ssafya109.yeogirok`, SHA-1 인증서 지문. 클라이언트 하나에 SHA-1 하나라서 **서명 키마다 하나씩** 만든다. 결과 클라이언트 ID는 어디에도 넣지 않는다. SHA-1이 없거나 다르면 앱에서 `DEVELOPER_ERROR`가 난다.
4. iOS 클라이언트는 iOS를 지원할 때 추가한다(MVP는 Android만).

```bash
# 로컬 개발 빌드(debug.keystore)의 SHA-1. 출력의 "SHA1:" 줄
keytool -list -v -keystore frontend/android/app/debug.keystore -alias androiddebugkey -storepass android -keypass android
```

Play 스토어로 배포하면 Play Console → 앱 무결성 → 앱 서명의 "앱 서명 키 인증서" SHA-1을 등록한다.

ARCore (`frontend/docs/ar-tip-poc.md`)

- Google Cloud에서 ARCore API를 활성화하고, 패키지 `com.ssafya109.yeogirok`와 그 APK 서명 SHA-1의 Android OAuth 클라이언트를 등록한다. 앱은 Keyless 인증을 쓴다. 실제 승인 성공은 기기에서 Host/Resolve 응답으로 확인한다.

### 6.4 AWS S3

| 용도 | 개발용 | 서버용 |
| --- | --- | --- |
| 사진 | `yeogirok-a109-photos-dev` | `yeogirok-a109-photos-prod` |
| 영수증 | `yeogirok-a109-receipts-dev` | `yeogirok-a109-receipts-prod` |

- 모두 서울 리전(`ap-northeast-2`), 퍼블릭 액세스 차단, SSE-S3 암호화이다.
- 수명 주기 규칙: 사진 버킷은 `tmp/` 아래만 1일 뒤 삭제(확정 파일은 `tip-photo/`·`record-photo/`), 영수증 버킷은 모든 파일 1일 뒤 삭제.
- 서버는 서버 전용 IAM 사용자의 접근 키로 접근한다. 키가 없으면 AWS SDK 기본 역할로 호출해 정리 작업이 `BusinessException`으로 실패한 기록이 있다(`infra/README.md` 9단계).
- 앱은 백엔드가 발급한 Presigned URL로 S3에 직접 올리고 받는다. 파일 크기 한도는 백엔드 설정(사진 20MB, 영수증 10MB)이 정한다.
- 접근 키는 Git·노션·메신저에 올리지 않는다.

### 6.5 Firebase Cloud Messaging

- 서버: Firebase 서비스 계정 키 JSON을 `base64 -w0 서비스계정.json`(또는 `openssl base64 -A -in 서비스계정.json`)으로 한 줄로 만들어 `FIREBASE_SERVICE_ACCOUNT_BASE64`에 넣는다. 값이 없으면 시작 로그에 경고가 남고 푸시만 보내지 않는다.
- 앱: `app.config.ts`가 `android.googleServicesFile`을 `GOOGLE_SERVICES_JSON` 또는 `./google-services.json`으로 지정하고, 앱은 기기 푸시 토큰(`getDevicePushTokenAsync`)을 받는다. 알림 채널은 `chat`이다.
- 확인 필요: Firebase 프로젝트 생성, Android 앱 등록, `google-services.json` 배치 절차는 저장소 문서에 없다. `frontend/docs/login.md`의 "Firebase 설정 파일을 요구하는 구성은 사용하지 않는다"는 FCM 도입(2026-11-11) 전 로그인 설정에 대한 문장이다.

### 6.6 GitHub·Mattermost·Let's Encrypt

- 5.6의 웹훅(Payload URL·`application/json`), 커밋 상태 토큰, Mattermost Incoming Webhook을 따른다.
- 인증서는 `certbot --nginx`가 발급·자동 갱신한다. `sudo certbot renew --dry-run`으로 갱신을 시험하고, 만료일은 `sudo certbot certificates`로 본다.

### 6.7 Android App Links 지문

`infra/docker-compose.yml`의 `ANDROID_APP_SHA256_FINGERPRINTS`에 커밋된 값이다(비밀 값 아님). 첫째는 Expo 템플릿 `debug.keystore`(개발 빌드), 둘째는 배포 키 지문이다. 값을 통째로 바꾸므로 디버그 지문도 같이 적는다. 빈 값을 넘기면 모든 앱에서 초대 링크가 앱으로 열리지 않는다.

### 6.8 그 밖

- 확인 필요: 루트 `README.md`(main)는 AI에 GMS(LLM)를 쓴다고 적지만, 서버 compose와 `infra/.env.example`에는 `GMS_KEY`가 주석으로만 있고 백엔드·AI 설정에서 쓰는 곳을 찾지 못했다. 지금 배포 구성에는 GMS 키가 없다.
- OCR 모델: ai 컨테이너가 처음 켤 때 PaddleOCR 공식 검출 모델을 내려받아 `ai-models` 볼륨에 둔다. 서버가 처음 켤 때 인터넷에 접속할 수 있어야 한다. 인식 모델 B30은 이미지에 들어 있다.

| 파일 | 내용 |
| --- | --- |
| `V1__init.sql` | 처음 스키마. Flyway 도입 전 Hibernate(`update`)가 만들던 스키마를 옮긴 것(2026-11-11). `user_push_tokens`도 만든다 |
| `V2__seed_travel_categories.sql` | 공통 카테고리 8개 표시명 (API-079) |

| `V4__create_regions.sql` | 추천 지역 계층(시·도, 시·군·구, 법정동 코드 앞자리) (API-078) |
| `V5__add_room_places_source_record_fk.sql` | `room_places.source_record_id` FK (`ON DELETE SET NULL`) |

- V1에 넣지 않은 것(대부분의 FK, ENUM 타입, 열 기본값, 부분 인덱스, DEFERRABLE 유니크 등)은 `backend/docs/08-flyway.md` 4절에 목록이 있다. 지금은 `varchar` + CHECK, 서비스 코드가 값을 넣는 방식이다.
- 접속: 서버 안 `docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'`, 노트북에서는 `ssh -i <키파일>.pem -L 15432:127.0.0.1:5432 <서버 계정>@<도메인>` 후 `localhost:15432`.
- Redis는 영구 데이터 저장소가 아니다. 멱등키(24시간), 로그인 세션(리프레시 토큰 해시), 채팅 전달·정리 목록 등에 쓰고 AOF로 재시작 뒤에도 남긴다.
- **DB 덤프 파일은 이 매뉴얼에 포함하지 않는다(만들지 않았다).** 필요하면 5.9의 `backup-db.sh`로 `pg_dump` 파일을 만든다. 공식 코스 데이터는 덤프 대신 5.10의 적재로 다시 넣을 수 있다(S3 `course-seed/` 묶음 필요).
